# Инструкция по обновлению базы данных и внедрению новых функций

## Изменения в базе данных

### 1. Выполнить SQL скрипт обновления БД

Запустите файл `DatabaseUpdate.sql` в SQL Server Management Studio:

```sql
-- Подключитесь к базе данных Rieltor
-- Выполните скрипт DatabaseUpdate.sql
```

Скрипт создаст:
- Таблицу `LeaseHistory` для хранения архивных договоров
- Поле `IsArchived` в таблице `Leases` для пометки архивированных записей
- Поле `TerminationReason` в таблице `Leases` для хранения причины расторжения
- Хранимую процедуру `sp_ArchiveLease` для переноса договоров в историю
- Представление `vw_ActiveLeases` для выборки активных договоров
- Триггер `tr_CheckLeaseExpiration` для автообновления статуса при истечении срока

### 2. Обновить модель Entity Framework

После выполнения SQL скрипта необходимо обновить модель данных:

1. Откройте файл `RieltorBD.edmx` в Visual Studio
2. Щелкните правой кнопкой мыши на дизайне
3. Выберите "Update Model from Database..."
4. На вкладке "Refresh" выберите таблицу `Leases`
5. На вкладке "Add" выберите новую таблицу `LeaseHistory`
6. Нажмите "Finish"
7. Сохраните изменения и пересоберите проект

Альтернативно, можно вручную добавить свойство в класс `Leases.cs`:

```csharp
public string TerminationReason { get; set; }
public bool IsArchived { get; set; }
```

## Основные изменения в приложении

### Удаление функции удаления договоров

**Файл:** `LeaseEditView.xaml.cs`
- Удалена функция `BtnDeleteLease_Click`
- Добавлена функция `BtnTerminateLease_Click` для расторжения договоров

### Новые возможности

1. **Расторжение договора с указанием причины**
   - Кнопка "📄 Расторгнуть договор" появляется только для активных договоров
   - При расторжении требуется указать причину и инициатора
   - Проверка на наличие неоплаченных платежей

2. **Запрет редактирования**
   - Завершенные и расторгнутые договоры нельзя редактировать
   - При наличии оплаченных платежей запрещено изменение:
     - Дат договора (начало/окончание)
     - Суммы ежемесячного платежа
   - Разрешено изменять только контактную информацию (при необходимости)

3. **История договоров**
   - Новый раздел "История договоров" в главном меню
   - Отображение всех завершенных и расторгнутых договоров
   - Фильтрация по статусу и поиск
   - Просмотр причины расторжения

### Статусы договоров

Теперь система использует следующие статусы:
- **Активен** - действующий договор, можно редактировать (с ограничениями)
- **Завершен** - договор истек по сроку, редактирование запрещено
- **Расторгнут** - договор расторгнут досрочно, редактирование запрещено

## Для демонстрации на защите диплома

### Ключевые моменты для презентации:

1. **Безопасность данных**
   - Договоры никогда не удаляются из системы
   - Все изменения сохраняются в истории
   - Соответствие требованиям законодательства о хранении документов

2. **Бизнес-логика**
   - Защита от случайного изменения условий оплаченного договора
   - Контроль задолженностей при расторжении
   - Автоматическое обновление статуса при истечении срока

3. **Юридическая корректность**
   - Фиксация причины расторжения
   - Определение инициатора расторжения
   - Сохранение полной истории взаимоотношений с арендатором

### Сценарий демонстрации:

1. Создать новый договор аренды
2. Показать, что активный договор можно редактировать
3. Добавить платеж со статусом "Оплачен"
4. Попытаться изменить сумму или даты - система запретит
5. Расторгнуть договор с указанием причины
6. Показать, что расторгнутый договор нельзя редактировать
7. Перейти в раздел "История договоров" и показать архив

## Примечания

- Если хранимая процедура `sp_ArchiveLease` не создана, система продолжит работу, сохраняя данные в основной таблице
- Для полноценной работы рекомендуется выполнить весь SQL скрипт
- Экспорт в Excel будет реализован в следующей версии
